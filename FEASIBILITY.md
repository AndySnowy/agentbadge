**Concept:** soulbound achievement badges for Agent ID holders (Concept A in CONCEPTS.md — recommended).

## 1. Architecture

### 1.1 Smart contract — `AgentBadge.sol` (single contract, BSC mainnet)

- **Language/tooling:** Solidity ^0.8.20, OpenZeppelin ERC-721, Foundry (already installed at `~/.foundry/bin/forge`). Tests in Foundry (local + fork tests against BSC mainnet state).
- **Soulbound:** override `_update` to revert on any transfer except mint (from zero address) and burn (to zero address). Badges cannot be sold or transferred — they are reputation, not assets.
- **Agent ID gate:** every mint function requires `IAgentID(0x60b9262456de011f7d15a54cdd8c48baaa8b022f).balanceOf(msg.sender) > 0`. Verified on-chain 2026-11-19: our wallet returns 1, symbol is "AI".
- **Badge types** (`uint8 badgeType`, one per address per type, enforced by `mapping(address => mapping(uint8 => bool)) minted`):

| ID | Badge | On-chain eligibility check |
|---|---|---|
| 1 | Verified Agent | Holds an Agent ID |
| 2 | Early Agent | Holds an Agent ID **and** total badges minted so far < 100 (first-100 scarcity) |
| 3 | Collector I | Holds an Agent ID + NFT(s) from ≥1 curated collection |
| 4 | Collector II | Holds an Agent ID + NFTs from ≥5 curated collections |
| 5 | Collector III | Holds an Agent ID + NFTs from ≥10 curated collections |

- **Curated collections:** an owner-managed list of ~12 ERC-721 contracts known to be Agent-ID-gated free mints (starter candidates — each to be verified on-chain during build: ERC-721, `balanceOf` works): Ptah Relics `0xe8C6b38b5E63377a96b268319b66638f772254bb`, Agentic404 mirror `0xc6d38bc5D854fDA20bD4473e9f3D0486747C178C`, GLOOP `0x587C303982187Ec578dF309d27670327b13202F8`, plus others from the user's own verified mint history. Eligibility counts distinct collections where `balanceOf(msg.sender) > 0` (cheap staticcalls, ~50k gas for 12 checks). Owner can add/remove collections (emits events); removals never revoke already-minted badges.
- **Token IDs:** `badgeType * 1_000_000 + serial` (serial = per-type counter). `tokenURI` returns an on-chain `data:` JSON with inline SVG art generated by badge type (no IPFS, no server — the token is fully self-contained and survives any hosting failure).
- **Owner permissions (disclosed, per hackathon rules):** owner = deployer wallet (`0xEc8E…Be2`). Owner CAN: add/remove curated collections, update badge art URIs, pause minting. Owner CANNOT: mint badges to anyone (minting is only by eligible holders themselves), burn/transfer user badges, change eligibility retroactively, or withdraw funds (the contract never holds funds — minting is free except gas). All of this is documented in NatSpec + README.
- **What the contract does NOT do:** no token, no fees, no approvals, no fund custody, no off-chain oracle. This keeps the red-line profile clean and the audit surface tiny.

### 1.2 Frontend — static site, zero hosting cost

- **Hosting:** GitHub Pages (free) on a `github.io` subdomain. No custom domain cost. (Repo must be public anyway for the open-source requirement.)
- **Stack:** single-page static site, vanilla JS + ethers.js via CDN. Wallet connect via injected provider (`window.ethereum` — Binance Wallet injects it). **No QR login, no pairing codes, no session storage** — standard injected-wallet connect only.
- **Pages/views:**
  1. **Home** — what AgentBadge is, the 5 badges with art + eligibility rules, live stats (total badges minted, unique holders — read from the contract via public RPC).
  2. **Mint** — connect wallet → eligibility check per badge (free `eth_call`s) → mint buttons (each mint is its own user-confirmed transaction; the user sees and confirms every action themselves).
  3. **My Badges** — the connected wallet's badges with art.
  4. **Board** — recent mints + holder count (reads `Transfer` mint events via public RPC; no backend).
- **Copy rules (red lines):** no "passive income", no "earn", no promised returns, no "Binance"/"BNB" in the name/domain. Badge language: "collectible proof of activity, no monetary value". Risk warning not needed (no trading), but a plain line stating badges have no financial value goes on the homepage.

### 1.3 Verification plan (BscScan + Sourcify, both free)

1. Build + test locally with Foundry (unit tests + mainnet-fork eligibility tests).
2. Deploy to **BSC Testnet** (free faucet BNB) and test end-to-end with the frontend.
3. Deploy to BSC mainnet from the agentic wallet (via `baw`, preview + execute back-to-back per usual practice).
4. Verify on **Sourcify** first (`forge verify-contract --verifier sourcify` — no API key needed, exact match).
5. Verify on **BscScan** (needs a free BscScan API key — the user creates one at bscscan.com in ~2 minutes, or verify via the BscScan web form with flattened source; either is free).
6. Publish the repo (contract + frontend + README with owner permissions disclosed) and link it in the hackathon submission.

**The math:** ~14 promotion days (Nov 24 → Dec 8) need ~2–3 genuine minters/day. Agent ID claims passed 100,000 (Oct 2026), so the audience exists; the work is reaching it.

**Where Agent ID holders actually are (legitimate channels only):**

2. **GLOOP community** (thecolony.ai / X) — 3,333 Agent ID wallets hold GLOOP; they are literally the target audience, and GLOOP is itself a hackathon entrant (community cross-pollination, not competition for users).
3. **Ptah / Agentic404 / free-mint communities** — the user's own world; these holders already chase Agent-ID-gated mints.
4. **BNB Chain + Binance Wallet community channels** (Discord/Telegram) — check their rules before posting; no spam, one genuine project announcement + answers to questions.
5. **People the user already knows** with Agent IDs (referrer @rinjani-cantik, KangDan, other agent operators) — a personal ask beats a broadcast.

**Mechanics that help (built into the product):**
- The **Early Agent badge (first 100)** creates genuine urgency without any promise of value.
- Badges are screenshot-able flexes — each minter sharing their badge is free distribution.
- Minting is free except ~$0.005 gas — the lowest possible friction for a real on-chain interaction.

**Rules (non-negotiable):** no paying for interactions, no fake accounts, no mass-registration schemes, no promising airdrops/returns, no spam. Any of these = disqualification, and Binance explicitly watches for it.

## 6. Risks (ranked)

1. **The 30-user gate (biggest risk).** Everything else is cheap and buildable; reaching 30 real Agent ID holders with a small X account is the true bottleneck. Mitigation: launch early (Nov 24), post consistently, go where the holders already are (GLOOP/Ptah communities), lean on the free + fun hook. If it fails, the project still exists as a shipped artifact + the Promotion Award route stands alone.
2. **Submission channel unknown.** The announcement names no form/link. Mitigation: find it in week 1 (check @BinanceWallet X, ecosystem page); worst case, submit via the Binance survey pattern used for the Promotion Award.
3. **Judging is subjective.** Innovation Award scores are the panel's sole determination. Mitigation: maximize the objective parts (live early, complete product, deep Agent ID integration, clean open-source repo, honest docs) and don't oversell.
4. **Project Awards are out of reach.** Metrics-based top 10 will go to established projects with large communities (e.g., GLOOP). Not a risk to manage — just don't count on it; the Innovation Award is the target.
5. **Gas spike.** Negligible (see §3 — even 20× is affordable).
